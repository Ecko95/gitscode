**Reconcile-first observation:** Confirmed structurally (not via a live logDebug — the forever-loop cadence isn't exercised by the vitest harness, which calls `tickOnce()` directly, so a temporary `logDebug` couldn't demonstrate the 5 s cadence anyway). The background fiber is `Effect.forever(Effect.sleep(TICK_INTERVAL_MS=5000ms).andThen(tickOnce()))` (`AutomodeDriver.ts:357-358`), and `tickOnce` called `supervisor.getSnapshot()` as its **first** line (old `:136`) unconditionally, before the mode/kill-switch gate (old `:139`). `getSnapshot` runs `readActivePeerCount` (delamain `listPeers` subprocess) + `readBudgetUsage` on every call. So with automode off, every 5 s tick paid the full peer-list + budget IO for a snapshot it immediately discarded. Premise confirmed.

**Summary:** Added a cheap `getPolicy()` accessor to the supervisor (reads `stateRef.policy` only, no IO) and hoisted the driver's mode/kill-switch gate above `supervisor.getSnapshot()`. When automode is off — the steady state — the tick now returns after the in-memory policy read and never runs the peer-list subprocess or budget read. When ON, `getSnapshot` still runs immediately after the gate and every downstream `snapshot.*` use is unchanged, so autonomous behavior is byte-equal (`snapshot.policy === state.policy`).

**Ponytail shortcuts:** none material. Test proves the fix via IO spies on the mocked delamain/usage layers (the two effects inside `getSnapshot`) rather than a standalone stub supervisor — lazier and tests the real perf win through the live supervisor. Skipped constructing a full 16-field `AutomodePolicy` stub.

**Residual risks:** Benign TOCTOU when ON — policy is read (`getPolicy`) then re-read inside `getSnapshot`; if policy flips between the two Ref.gets the tick may act on the pre-flip policy, identical in effect to the flip landing one tick later. Single-fibered per tick, so no correctness impact.
