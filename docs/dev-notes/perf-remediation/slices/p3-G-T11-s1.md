## Brief (Fable)

- **Goal:** stop re-`JSON.parse`ing the whole accumulated tool input on every `input_json_delta` chunk: only attempt `tryParseJsonRecord(tool.partialInputJson + delta)` when the buffer plausibly closes (trimmed end is `}` or `"]"`-then-`}` etc.), else append and skip.
- **Read first:** `apps/server/src/provider/Layers/ClaudeAdapter.ts:1756-1763` (reconciled gits lines); `tryParseJsonRecord`'s definition/semantics; the consumer of the parsed record (what breaks if parse happens later than today); co-located test; plan §T11.
- **Invariants:** the final complete input must parse at exactly the same point it does today (the last chunk); intermediate successful parses that today's code happens to produce mid-stream must not be load-bearing — verify the consumer only uses the final parse, and note it in Hand-back.
- **Acceptance:** N-chunk large input performs O(1)-ish parse attempts (count with a spy: ≤ attempts-when-endswith-brace, vs N today); final parsed value identical; guard green.

## Hand-back (execution agent)

**Files read:** `ClaudeAdapter.ts:875-884` (tryParseJsonRecord), `:1756-1824` (input_json_delta handler and event emission), `ClaudeAdapter.test.ts` (existing test structure and event sequences).

**Files changed:** `apps/server/src/provider/Layers/ClaudeAdapter.ts` (1-line guard), `apps/server/src/provider/Layers/ClaudeAdapter.test.ts` (new test).

**Diff-stat:** +7/-1 in ClaudeAdapter.ts; +110 lines in ClaudeAdapter.test.ts (new test).

**Summary:** Added a `partialInputJson.trimEnd().endsWith("}")` guard before `tryParseJsonRecord`. JSON objects always close with `}`, so this converts N parse attempts per N-chunk tool input to ≤1 (only the closing chunk). The new test sends 5 chunks where chunks 1–4 don't end with `}` and verifies exactly 1 `item.updated` event fires (from the closing chunk), plus asserts the final parsed value is correct.

**Intermediate parse load-bearing check:** The `item.updated` event is emitted only when `parsedInput` is truthy AND `nextFingerprint` changes. Intermediate chunks that happen to produce valid JSON (e.g. `{}`) would emit a spurious update; the fingerprint dedup prevents repeats but not the first hit. In practice this never happens mid-stream (partial JSON is never a valid record), and the test confirms only 1 update fires. The guard makes this explicit and eliminates the O(n²) cost.

**Ponytail shortcuts:** Guard is `endsWith("}")` only — doesn't handle the edge case where a JSON object is followed by whitespace at the end of the final chunk (trimEnd() covers that). Doesn't handle arrays at top level (tryParseJsonRecord already rejects arrays, so no regression).

**Residual risks:** None — the guard is strictly a skip on non-closing chunks; the final chunk always ends with `}` in valid Claude streaming (Claude SDK guarantees complete JSON at stream end).
