## Findings by category

### 1. Architectural risks

- **P0 — Thread deletion never removes worktrees.** `apps/server/src/orchestration/Layers/ThreadDeletionReactor.ts:58-64` stops sessions and closes terminals but leaks the worktree. Nothing else ever deletes it. ~3-line fix plus a reaper.
- **P0 — No projection rebuild path.** Projections (`ProjectionPipeline.ts`, `ProjectionSnapshotQuery.ts` — 2,172 lines) are applied live with no drift detection and no rebuild-from-events capability. One bad migration = silent, unrecoverable read-model corruption.
- **P1 — Single-threaded orchestration queue** (`OrchestrationEngine.ts:90,303`): every command serializes through one fiber; one slow command blocks all threads. Known ceiling — document, don't redesign yet.
- **P1 — OrchestrationEvents grows forever** (`persistence/Services/OrchestrationEventStore.ts`, no retention/archival).
- **P2 — SQLite WAL untuned** (`persistence/Layers/Sqlite.ts:35`): no `busy_timeout`, `wal_autocheckpoint`, or `synchronous` pragma — matters at target concurrency.

### 2. Android-specific risks (apps/mobile is a native Expo app)

- **P0 — `android:usesCleartextTraffic=true`** shipped unconditionally (`apps/mobile/plugins/withAndroidCleartextTraffic.cjs:14`). Credentials and agent traffic ride unencrypted HTTP if anything falls off the Tailscale path.
- **P1 — Composer/keyboard overlap risk** on older Android (`apps/mobile/src/app/_layout.tsx:96`; no adjustResize equivalent verified).
- **P2 — Expo update check blocks cold start** (`apps/mobile/app.config.ts:64-68`, `fallbackToCacheTimeout: 0`) — 5–10s hang on flaky links.
- **P2 — Web-on-phone:** sidebar assumes >500px; hover-only delete actions (`apps/web/src/components/Sidebar.tsx`).

### 3. Offline-first risks

- **P0 — No in-flight turn recovery.** If the WebSocket drops mid-turn, the server finishes the turn but the client has no resume/catch-up protocol (`packages/client-runtime/src/wsTransport.ts:126-212`).
- **P1 — Token expiry dead-end:** no 401 → re-auth flow; client shows "reconnecting" forever (`apps/web/src/rpc/wsConnectionState.ts`).
- **P1 — Unary RPCs silently dropped while disconnected** (`wsTransport.ts:91-101`) — settings-class writes vanish.
- **P1 — Resubscribe gaps** after reconnect can silently lose events; client has `snapshotSequence` but doesn't gate stale detail events against it (`apps/web/src/store.ts:54-96`, `apps/server/src/ws.ts:886-906`).
- **P2 — Heartbeat timeout doesn't flip UI to disconnected** (`wsConnectionState.ts:171-176`). No service worker — acceptable for a dev tool, deliberately ignored.

### 4. Dependency risks

- **P0 — `claude-agent-sdk` two minors apart** between server (`^0.3.154`, `apps/server/package.json:26`) and scripts (`^0.2.77`, `scripts/package.json:10`).
- **P0 — React mismatch:** web 19.2.6 vs mobile 19.2.3 (plus react-dom, @types/react).
- **P1 — 9 of 16 catalog entries missing from `overrides`** (root `package.json:75-84`) — transitive drift bypasses the catalog.
- **P1 — `node-pty` floating (`^1.1.0`)** — a trusted native dep with shell access should be exact-pinned (`apps/server/package.json:34,101`).
- **P1 — `effect@4.0.0-beta.73` patch** (13KB, RPC types, `patches/`): a beta bump silently un-applies it.
- **P2 —** TypeScript `native-preview` dev snapshot in the toolchain; mobile `file:` deps instead of workspace packages; stale `react-native-nitro-modules` patch.

### 5. State management problems

Four sources of truth for thread state (event log → projections → in-memory provider runtime → client atoms), with two reconciliation gaps:

- **P1 — Client shell/detail resequencing race** after reconnect (see 3).
- **P1 — Codex `thread/resume` fails silently to a fresh session** — conversation context lost with only a swallowed error (`apps/server/src/provider/Layers/CodexSessionRuntime.ts:476-490`).
- **P2 —** Module-global mutable Maps in `apps/server/src/gits/mcp/VisualPlanMcpRegistry.ts:23-25` — low QPS, acceptable; mark with a `ponytail:` ceiling comment.

### 6. Testing gaps

Coverage is respectable (server 31%, web 25%, orchestration deciders well-tested, no skipped tests) but inverted vs risk:

- **25 of 32 migrations have zero tests** — highest blast radius in the repo (data loss on upgrade). A harness pattern already exists (`016_CanonicalizeModelSelections.test.ts`).
- **Auth trust boundary half-untested** — 7 of 14 files (`ServerAuth`, `AuthControlPlane`, bootstrap flow).
- **No WebSocket reconnect scenario tests**; no provider spawn→kill→reap lifecycle test; no concurrent-load orchestration test.

### 7. Build/release gaps

- **P1 — Zero required checks.** CI runs Format/Lint/Typecheck/Test/Build but nothing blocks merge. With autonomous agents merging PRs this is the single biggest drift enabler.
- **P2 — `build` doesn't depend on `typecheck`** in `turbo.json:42-46` (typecheck cache is disabled — consistent with known stale-cache pain).
- **P2 — Release versioning is a hand-rolled script** patching 4 package.json files (`release.yml:233`); nightly tag grep handles two formats inconsistently (`release.yml:45`). Signing and secret masking are fine.

### 8. Autonomous-agent drift surfaces

1. **No required CI** — drift merges unreviewed (see 7).
2. **Sequential migration numbers with no collision check** — two peers both create `033_*.ts`; last-loaded silently wins.
3. **Conventions documented but not enforced:** `AGENTS.md:32` bans barrel imports of `@t3tools/shared`; no oxlint rule exists.
4. **Per-adapter duplicated error classifiers** (`ClaudeAdapter.ts:310-327` + Codex + Cursor equivalents) — agents fix one copy, not three.
5. **Version drift channel:** agents adding deps per-workspace bypass the catalog because overrides are incomplete (see 4).

### 9. Refactors before adding features

1. Event-log retention + projection rebuild command (restores confidence in everything event-sourced).
2. Reconnect/resync protocol (unblocks mobile + VPS remote usage).
3. Catalog/overrides unification + migration collision guard (unblocks safe parallel-agent development).
4. Extract shared `ProviderErrorClassifier` (before adding a 4th provider).
5. Over-engineering cuts: only ~142 lines (adapter Shape marker interfaces, unused `runtimeLayer` intermediate exports). Lean already otherwise.

## Specs for the top 5 fixes

### Spec 1 — Worktree lifecycle closure

**Problem:** `ThreadDeletionReactor.processThreadDeleted` (`ThreadDeletionReactor.ts:58-64`) closes terminals/sessions but leaks the thread's worktree; nothing else ever deletes it.

**Change:**
1. In `processThreadDeleted`, resolve the thread's worktree path and call the existing `removeWorktree` (`GitVcsDriverCore.ts:2142`) with `--force` fallback, idempotent on "not found".
2. Add a reaper sweep (clone the `ProviderSessionReaper` pattern) over `worktreesDir` removing unreferenced worktrees older than `GITS_WORKTREE_MAX_AGE_MS` (default 7 days), gated by `GITS_ENABLE_WORKTREE_REAPER`.

**Never:** touch paths outside `worktreesDir`. Log every removal.

**Accept:** deleting a thread removes its worktree; test proves stale-unreferenced removed / referenced kept; `git worktree list` shows no dangling entries after sweep.

### Spec 2 — Reconnect resilience protocol

**Problem:** three composable gaps: detail events older than `snapshotSequence` applied after reconnect (`apps/web/src/store.ts:54-96`); heartbeat timeout doesn't change connection phase (`wsConnectionState.ts:171-176`); 401 after token expiry loops forever.

**Change:**
1. Client discards detail events with sequence ≤ the shell snapshot's `snapshotSequence` and refetches the snapshot on resubscribe. Server asserts `live.sequence > snapshotSequence` on subscribe (`ws.ts:886-906`) and logs gaps.
2. `onHeartbeatTimeout` transitions phase → `disconnected` so the reconnect banner shows.
3. On 401 during reconnect, surface the re-pair flow instead of retrying forever.

**Accept:** integration test: subscribe → kill socket mid-turn → reconnect → client state equals server projection (no stale turn state). Heartbeat-timeout test flips phase. 401 test lands on re-auth UI.

### Spec 3 — Dependency coherence + merge gate

**Problem:** catalog has 16 entries, overrides only 8 (root `package.json:75-84`); react 19.2.6/19.2.3 split; claude-agent-sdk `^0.3.154`/`^0.2.77`; `node-pty` floating with native/shell access; no required CI checks, so none of this stays fixed.

**Change:** add the 9 missing overrides; bump mobile react stack to web's versions; unify claude-agent-sdk to `^0.3.154`; pin `node-pty` exact `1.1.0`; enable branch protection on `gits` requiring the `quality` job.

**Accept:** `bun install --frozen-lockfile` clean; one version of react/react-dom/@types/react in `bun.lock`; typecheck + tests green; a test PR cannot merge with a failing quality job.

### Spec 4 — Migration safety for parallel agents

**Problem:** 25/32 migrations untested; sequential numbering means two concurrent peers can both create `033_*` and one silently loses.

**Change:**
1. Startup guard in the migration loader: duplicate or non-contiguous numbers = hard boot failure with a clear message.
2. Batch tests for data-mutating migrations 010–032 using the `runMigrations({ toMigrationInclusive })` harness from `016_CanonicalizeModelSelections.test.ts` — seed pre-state, migrate, assert post-state. Pure-DDL migrations may be skipped with a one-line justification.

**Accept:** duplicate-number fixture fails boot in a test; each data-mutating migration has a test; CI runs them.

### Spec 5 — Android transport hardening

**Problem:** `withAndroidCleartextTraffic.cjs:14` sets `usesCleartextTraffic=true` for all variants.

**Change:** apply the plugin only when `process.env.APP_VARIANT === "development"`; production/preview builds get the Android default (cleartext off). Add a startup warning banner in dev builds when the server URL is `http:`.

**Accept:** production `AndroidManifest.xml` (from `expo prebuild`) lacks the attribute; dev build still connects to local `http:` targets.

## Review checklist for Codex peers

Every PR against `gits` gets checked for:

### Process
- [ ] Branched off `origin/gits`, PR base `gits`; Format/Lint/Typecheck/Test/Build all green (turbo typecheck cache is untrusted — confirm a fresh tsgo run)
- [ ] No repo-wide `bun fmt` — only touched paths formatted
- [ ] Conventional commit format; diff contains only the task's scope

### Correctness / architecture
- [ ] Any spawned process/fiber/queue is scope-bound with a finalizer (no detached spawns, no `Queue.unbounded` — use bounded)
- [ ] No new module-global mutable state; no `catchAll` that swallows typed errors (use `catchTag`)
- [ ] New DB migration: next contiguous number, has a test (pre-state → migrate → assert), never edits an existing migration
- [ ] Events/projections: no direct projection writes outside `ProjectionPipeline`; new events are additive
- [ ] Timers/polling loops: env-tunable interval, documented default, off-switch if non-essential

### Drift guards
- [ ] Deps added via root catalog + overrides, never a one-off workspace version; no new dep where stdlib/Bun/Effect suffices
- [ ] `@t3tools/shared` imported by subpath only; helpers reused (grep before writing — no 4th error classifier)
- [ ] Conventions come from neighboring code, not invention; deliberate shortcuts marked `ponytail:` with the ceiling named
- [ ] Docs updated only where behavior changed; no restating code in prose

### Client-facing
- [ ] Works at 375px width and without hover; WebSocket-delivered state handles reconnect (sequence-gated, no optimistic state that can't reconcile)
